## 2.7 PyTorch模型导出ONNX

　　模型训练完后，我们已经有了保存的权重。能否直接把它交给后续工具识别手写数字？本例的权重文件只保存参数，还需要对应的模型定义，才能还原从图片到分类输出的计算过程。

　　2.6节展示了同一计算如何用ONNX节点表达。本节把恢复好的PyTorch模型转换为ONNX文件，这个过程称为导出，不需要重新训练。我们先准备模型和样例输入，再生成文件，检查结构、接口与输出。文件生成后，还要在相同输入下比较输出，才能进一步判断导出前后是否一致。

　　本节使用配套工程的`src/main.py`和`model/mnist_cnn.pt`，完整导出程序为[scripts/export_onnx.py](../../02-onnx-baseline/scripts/export_onnx.py)。模型定义、权重和已有ONNX的版本记录见[模型版本记录](../../02-onnx-baseline/docs/model-version.md)。完整安装与运行步骤放在[工程README](../../02-onnx-baseline/README.md)，正文只展开关键部分。

### 2.7.1 恢复模型状态

　　本例权重文件中的参数字典没有完整描述`forward()`。恢复模型时，需要先创建相同的`Net`，再加载权重：

```python
model = Net().cpu()  # 创建原模型结构，并在CPU上工作。
state = torch.load(args.weights, map_location="cpu", weights_only=True)
model.load_state_dict(state, strict=True)  # 参数键名和形状必须匹配。
model.eval()                             # 关闭Dropout的训练行为。
```

　　这里的`Net`和命令行参数`args`由完整脚本准备。加载时，`strict=True`可以检查参数缺失、额外参数或形状不匹配等问题。本例的8个参数张量已经与仓库中的Net严格匹配，说明权重能装入该结构；识别是否准确，还需要数据评估。[记录：M02-002]

　　最后一行为什么还要调用`eval()`？本模型有两处Dropout，训练时随机丢弃部分特征，评估时直接传递输入。要导出用于推理的模型，就应先切换到评估模式。这也解释了图2.6.1中Dropout节点的省略。评估模式决定相关层的行为，“不计算梯度”则决定是否记录梯度计算，两者作用不同。仅使用无梯度上下文，不能代替`eval()`。[来源：S02-005；记录：M02-001]

### 2.7.2 定义样例输入

　　恢复模型之后，还要告诉导出器怎样调用它。一次输入一张MNIST图片，对应的样例张量可以这样构造：

```python
example = torch.zeros(1, 1, 28, 28, dtype=torch.float32)  # NCHW固定形状。
```

　　这个形状与2.6节一致：1张图片、1个通道、28像素高、28像素宽。这里填零，是因为需要一个符合接口的样例来说明调用与形状，并不测试识别效果。零张量也不能证明前处理正确；后面比较模型输出时，需要另准备固定输入，让两边接收完全相同的数值。

　　本节采用的接口见表2.7.1。

<p align="center">表2.7.1 本例导出接口</p>

| 字段 | 输入 | 输出 |
| --- | --- | --- |
| 名称 | input | log_probs |
| 数据类型 | float32 | float32 |
| 固定形状 | [1,1,28,28] | [1,10] |
| 含义 | 与训练前处理一致的单张MNIST灰度图张量 | 10类对数概率 |

　　接口名称由导出脚本设置，形状和类型已经从实际ONNX文件读取。[记录：M02-001、M02-003]

　　输入输出名称是图接口的标签，后续工具可以据此找到对应张量。这里将输出命名为`log_probs`，提醒使用者模型末端是LogSoftmax，输出不是未经变换的原始分数。改名不会改变计算，也不会改变输出含义。[来源：S02-005]

### 2.7.3 选择导出设置

　　opset该选哪个版本？要看接收这份ONNX的运行时或编译器支持哪些算子规则，不能只选最新版本。[来源：S02-005] 目标平台的软件开发工具包（software development kit，SDK）版本及支持范围在本例中没有指定，因此配套脚本保留`--opset`选项；省略时使用当前导出器的推荐值。已经生成的文件实际使用opset 20，但这个值不是面向所有设备的推荐值。

　　面向具体工具时，可按表2.7.2逐项核对。该表说明核对方法，不替代指定SDK的官方支持依据。

<p align="center">表2.7.2 导出设置与目标工具核对表</p>

| 需要核对什么 | 为什么要核对 | 记录什么 |
| --- | --- | --- |
| 芯片、SDK和转换工具版本 | 同一平台不同版本的支持范围可能不同 | 官方支持表的版本与位置 |
| 模型opset及实际算子 | 支持某个opset并不自动证明所有算子属性都适用 | 算子及属性限制 |
| 输入形状（shape）、数据类型（dtype）和布局（layout） | 工具可能要求固定尺寸或特定接口形式 | 实际使用的输入约定 |
| 动态维度及其取值范围 | 模型与工具可能只支持部分动态情形 | 允许变化的轴及约束 |

　　本节一次处理一张28×28图片，不声明动态维度，先建立固定形状的模型。以后若要一次处理多张，可以研究动态批次；若要改变图片尺寸，还必须检查模型结构。2.6节中得到的9216是当前全连接层要求的特征数量，不能随意更改。因此，添加动态维度参数并不会自动让模型接受任意图像尺寸。

　　在本节对应的现代导出路径中，动态输入形状通过`dynamic_shapes`描述；旧的`dynamo=False`路径使用`dynamic_axes`。两套参数应按所用PyTorch版本和导出路径区分，不宜从不同版本教程中拼接。[来源：S02-005] 本例没有进行动态导出实验，因此保留固定形状，并将动态策略作为后续按实际需求修改的接口选项。

### 2.7.4 导出与保存

　　准备好模型、样例输入和导出设置后，调用导出接口：

```python
program = torch.onnx.export(
    model,
    (example,),                  # 只有一个输入，也用元组传入。
    input_names=["input"],
    output_names=["log_probs"],
    opset_version=args.opset,    # 与接收模型的工具版本核对。
    dynamo=True,                # 使用基于torch.export的导出路径。
    optimize=False,             # 关闭可选图优化，便于保留初始版本。
)
program.save(args.output, external_data=False)  # 本小模型保存为单个文件。
```

　　`torch.onnx.export()`把模型计算转换为ONNX节点，得到包含该图的ONNXProgram；`save()`再把它写入文件。`optimize=False`关闭的是可选图优化，并不要求导出器逐行照抄源码。导出本身需要转换计算的表达方式，因此设置这个参数后，仍可能出现2.6中的Reshape和Dropout省略。[来源：S02-005；记录：M02-003]

　　本例模型较小，使用`external_data=False`把图和权重保存到一个ONNX文件中。大型模型可能需要外部权重数据，此时必须同时保存与分发这些文件；不能只传递一个不完整的主文件。[来源：S02-005]

　　配套脚本默认读取工程内的`model/mnist_cnn.pt`，写入`outputs/mnist_cnn.onnx`。它先检查目标是否存在，避免覆盖已有导出；需要重新导出时，可以用`--output`指定新文件名。脚本依据自身位置寻找默认目录，不要求把某台电脑的盘符写入程序。

### 2.7.5 核对导出结果

　　文件生成后，还需要检查结构、接口和数值。第一层检查文件是否符合ONNX的结构规则：重新读取磁盘上的文件，再调用ONNX checker。

```python
exported = onnx.load(args.output)  # 检查磁盘上实际保存的模型。
onnx.checker.check_model(exported)
```

　　当前产物已经使用ONNX 1.23.2重新读取并完成此检查。读取文件还可以得到生产者PyTorch 2.14.1+cpu、IR版本10、ai.onnx opset 20，以及主图的13个节点。这些都是已保存文件的实际信息。[记录：M02-003] 不过，checker检查的是结构规则，还没有拿图片执行模型，不能由此推断识别结果或目标硬件兼容性。[来源：S02-006]

　　第二层是接口检查。实际读取的输入为`input`、FLOAT、`[1,1,28,28]`，输出为`log_probs`、FLOAT、`[1,10]`。其中FLOAT在本例表示float32。这些字段与表2.7.1一致。Netron还可以辅助查看连线、属性和末端LogSoftmax，但它不能替代checker或数值比较。

　　第三层是数值回归：即使结构和接口符合预期，也要使用固定输入，检查转换前后的输出是否在约定范围内一致。[来源：S02-008] 可以先保存一份经过前处理的输入张量，再把完全相同的数值分别提供给PyTorch与ONNX执行后端，排除各自读图或归一化造成的输入差异。

　　本例的训练前处理包括ToTensor，以及均值0.1307、标准差0.3081的归一化。用于真实图片对比时应沿用这一约定，同时保持float32、NCHW和相同批次；具体执行ONNX的接口留到2.8展开。[记录：M02-001]

　　比较时先看输出形状是否相同、数值是否有效，再查看10个对数概率及最大值所在类别。两边预测出同一个数字，只能说明类别一致，不能说明各项数值足够接近：两组数值即使相差较大，最大值的位置也可能相同。

　　对每个输出元素，记PyTorch参考值为$a$，ONNX对比值为$b$，则绝对误差$e_{\mathrm{abs}}$为

$$
e_{\mathrm{abs}}=|b-a|
$$

　　当$a\ne0$时，相对误差$e_{\mathrm{rel}}$可以定义为

$$
e_{\mathrm{rel}}=\frac{|b-a|}{|a|}
$$

　　参考值为零时，相对误差的上述定义不适用；接近零时，该比值也可能放大很小的绝对差异。因此，应同时报告绝对误差，并明确相对误差的零值处理规则。容许误差应在比较前依据任务要求约定，不把某次观察值临时当成“通过标准”。

　　实际判断时，可以把绝对容差与相对容差结合起来。设绝对容差为$t_{\mathrm{abs}}$、相对容差为$t_{\mathrm{rel}}$，要求每个元素满足

$$
|b-a|\leq t_{\mathrm{abs}}+t_{\mathrm{rel}}|a|
$$

　　右侧第一项照顾参考值为零或接近零的情况，第二项随参考值的大小调整允许差异。这个判据不需要除以参考值，但仍要先检查两侧形状相同、所有数值有限。通过检查只说明所选输入在这组容差下保持一致，不能代替整个测试集的准确率评估，更不能证明板端执行结果。

　　配套的[数值回归脚本](../../02-onnx-baseline/scripts/compare_outputs.py)将PyTorch输出作为参考，在检查形状和有限值之后执行以下核心计算。这里的reference和actual分别表示两侧原始输出，先转为float64计算差值，以减少误差统计本身的舍入影响；模型推理仍使用float32。

```python
error = np.abs(actual.astype(np.float64) - reference.astype(np.float64))
passed = bool(np.all(error <= atol + rtol * np.abs(reference)))
```

　　本次使用MNIST测试集前10张图片，按前述方法归一化，在CPU上逐张执行；PyTorch处于评估模式，ONNX由ONNX Runtime 1.31.0的CPU执行后端运行。比较前固定绝对容差为$10^{-5}$、相对容差为$10^{-4}$，这只是本次教学实验的判据。10张图片共100个输出值均满足联合容差，预测类别也全部一致；最大绝对误差约为$5.72\times10^{-6}$。[记录：M02-004]

　　为什么最大相对误差却约为2.38%？它来自索引3的图片、类别0的输出：参考值约为$-5.01\times10^{-6}$，两侧绝对差异约为$1.19\times10^{-7}$。参考值接近零，除法放大了差异的比例，但绝对差异仍小于预先约定的绝对容差。另外有1个参考值恰为零，不参与相对误差统计，两侧该值均为零。这正说明相对误差必须结合参考值和绝对误差解释，不能单独作为结论。[记录：M02-004]

　　本次输入、标签、两侧原始输出和逐样本结果均已保存，位置及校验值见[实验记录](../../reports/ch02/E02-07-20261016-01/README.md)。这个结果只覆盖上述10张图片，不是完整测试集准确率，也不能推断板端兼容性。如果以后更换权重、导出设置或输入处理，应重新执行对比；结果不一致时，再依次检查模型版本、评估模式、输入处理、输出对应关系及导出设置。

### 2.7.6 管理模型版本

　　假设后来又导出了一次模型，文件名仍叫mnist_cnn.onnx。怎样知道它与第一次是否相同？仅凭文件名无法区分，需要比较文件校验值，并找到生成它的模型定义、权重和导出脚本。本例已将这些材料关联记录，同时保存了源码、权重和ONNX的SHA256，完整值见配套版本记录。

　　保留原始文件后，还可以研究模型简化。例如，2.6中用于计算展平目标形状的分支，包含几个节点，结果却是一个固定形状。在满足等价条件时，可以提前计算其中只依赖常量的部分，这称为常量折叠；它与其他图优化都可能生成派生版本。ONNX Simplifier是候选工具之一，但本工程尚未选定其发行版，也没有生成简化结果。[来源：S02-009] 节点减少不代表输出一定保持一致，也不代表运行一定更快。

　　本例文件可按表2.7.3管理。

<p align="center">表2.7.3 模型材料与派生关系</p>

| 材料 | 工程内位置 | 记录要求 |

　　无论是简化、固定输入尺寸，还是修改算子，得到的都是需要重新检查的新模型。应另存文件，再执行结构检查、接口核对和同输入数值回归。旧模型的对比结果不能直接用来证明新模型正确。

　　导出后，应保留接口明确、版本可追溯的ONNX文件及回归记录。下一节将进一步展开ONNX Runtime的使用，建立可复用的基线推理。面向具体芯片时，还要按照对应SDK核对算子和形状支持；PC上的结构检查与数值回归不能替代板端验证。
