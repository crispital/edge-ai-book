## 2.8 ONNX Runtime基线推理

### 知识点
1. ONNX Runtime Session、输入元信息与输出读取。
2. 沿用PyTorch相同图片、dtype、布局和归一化构造输入。
3. 比较原始输出、预测类别、绝对误差与相对误差。
4. 建立可保存、可复用的基线，区分模型、导出、前处理和后处理问题。

### 配套产出
- 基线推理及输出对比代码。
- 固定样本与真实结果。

承接2.7已导出的模型，不重讲训练和导出教程。Windows CPU为本机参考运行环境；对比需使用同一权重、评估模式与同一输入。误差判定方法、容差与运行环境在实际实验中明确，不预填通过结论。

## 2.9 面向硬件部署的模型接口

### 知识点
1. 模型来源、版本、输入名称、shape、dtype与layout。
2. 灰度或颜色顺序、Resize/Crop、归一化和像素值范围。
3. 输出名称、形状、语义、类别表及后处理规则。
4. 分类接口如何扩展到检测、分割、OCR，接口变化如何触发代码调整。

### 配套产出
- 模型接口模板。
- MNIST已填写示例：代码可确认的字段注明来源；需从实际ONNX读取的字段待交付后填写。

## 4.1 为什么需要轻量化

### 知识点
1. 以统一MNIST模型展示参数量、明确格式的模型文件大小与PC推理耗时。
2. 对照1.5内存、时延、功耗等资源约束，解释各项指标能说明什么。
3. 精度要求与资源预算共同决定是否压缩及压缩目标。
4. 说明PC端压缩与筛选、平台端适配与实测的衔接，不把预期当结果。

### 配套产出
- 基线度量报告。
- 资源预算与压缩目标表。

沿用2.8基线和2.9接口，与4.2对齐测量方法。详细度量教程归4.2；本节保留真实测量和解释责任。MNIST示例不必然超过端侧预算；只有明确约束及实测支持时才判断是否需要压缩，不能为了动机编造“过大、过慢、超限”。PC时间不能代替板端时间，文件大小不能代替峰值内存，尚未测量的功耗保持未知。
