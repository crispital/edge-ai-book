05

能追到具体文段的工作记录

工作事件用 JSONL；提示词和原始输出保留完整快照。

这段文字，是谁在何时怎样生成的？

时间 + subagent ID→实际提示词 + SHA256→原始输出快照→文段 ID + SHA256→稿件路径 + 版本

记录请求模型与已知实际设置，未知值保留 null。后续改写新增事件关联原事件；没有真实调用，就不填写生成记录。

你要找什么去哪里找怎么关联
工作日志docs/logs/YYYY/MM/YYYY-MM-DD.jsonlL 事件 ID；同名 Markdown 为阅读摘要
任务卡、缺口与修改意见docs/ch02|ch04/小节工作记录.md每节一份工作笔记，避免重复台账
来源卡、资料笔记docs/references/ch02|ch04/notes/S 来源 ID，索引定位原资料与引用位置
实际提示词与 AI 输出docs/references/ch02|ch04/ai-records/A记录ID/input.md / output.md / review.md
实验计划与执行证据reports/ch02|ch04/E记录ID/plan、report、原始记录；大输出另列保管位置

06

Agent 与 Git 各管什么

规则入口保持简短，详细流程按任务读取。

Agent：按材料与提示词工作

AGENTS.md 是入口，详细要求在 docs/。当前不另建 skill，避免重复维护。

  • 常规任务：gpt-6.1-sol / medium。
  • 复杂调度可用 gpt-6-astra / medium；禁止 Fast。
  • 后续 AI 撰文调用带明确提示词与材料的 subagent。
  • 指定文件所有权，有依赖的任务串行。
  • 运行设置需实际确认，文档本身不负责切换模型。

任务分支按当前章、节命名；已有历史分支不自动改名。

上传代码、文档和必要证据；完整数据与模型本地保存.gitignore 控制上传范围，.gitattributes 统一文本换行及二进制处理。原参考书、原始团队文件、完整数据、权重、视频、缓存和凭据不直接上传；用清单、版本、校验值和合法获取方式交接。
