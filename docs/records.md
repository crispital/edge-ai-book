# 工作日志与各类卡片

## 单一记录原则

工作日志记录“本次做了什么、文件在哪里、实际检查如何、接下来缺什么”；卡片保存任务或资料的详细内容。日志只链接卡片，不复制全文。正文、资料、图表和实验保留各自目录，不重新复制到日志附件。

指南允许任务与资料记录合并到工作笔记。本仓库据此约定每个小节一份工作笔记，不要求每一个问题或资料另建文件。下列路径是个人仓库新增归档约定，不声称指南已经规定这些文件名。

## 工作日志

周提交和交稿说明保留[指南八项模板](../CONTRIBUTING.md#提交说明指南原文)全部字段；下面的日常日志结构不能替代它。

每个实质工作批次追加当日日志：目的与输入版本 → 实际完成 → 产出路径 → 实际验证 → 未完成与下一步。按任务拆分事件，不记录所有聊天或每一条工具输出。新日期创建新文件，不反复覆盖历史日志。

新工作使用 JSONL 事件作为结构化依据，schema 及字段说明见 [logging-schema.md](logging-schema.md)。Markdown 只汇总这些事件及早期已有记录，不另外维护冲突的事实。早期记录缺乏精确时间时保留原记录，不补造时间或 subagent 调用。

每周提交说明可直接作为相应日期日志的一个段落，附本周事件和文件链接，无需另建一套周报台账。只有用户要求对外发送时才发送；存仓库记录本身不等于已经通知任何人。

同一天多个 agent 参与时指定唯一日志整合者，其他 agent 返回记录片段，由整合者追加。变更或纠错用后续记录说明，不静默改掉既有执行结论。

## AI 记录

一次 A 目录包含：
- input.md：实际填充后的完整提示词、模板版本、输入文件及版本/提交、读取位置、模型配置、范围与所有权。
- output.md：原始返回内容。
- review.md：作者核对、修改与确认状态，引用最终产出位置。
- 确需单独保存确认稿时使用 confirmed.md；否则链接已有正式稿，不复制两份。

未经确认的输出不会自动进入正文。包含受限或私人材料的完整输入保存到 .local/ai-records/，共享记录只写版本、可定位位置及校验值。记录“待保存”“未确认”必须符合事实。

实际文段生成对应 passage_generated 事件，绑定 A 目录中的提示词与输出快照、真实 agent ID、时间、目标稿件、稳定文段 ID 及 SHA256。修改后追加关联事件，不覆盖原始快照。schema 的示例文件不属于正式工作记录。

## 实验记录

正式 E 目录保存 plan.md、report.md 及 raw/ 中可共享的实际命令输出和环境记录。原始输出不改写；报告可以选取代表性结果，但需指向完整记录。大输出用 manifest.md 列明文件、SHA256、大小、实际保管位置及合法获取方式，保存在 .local/runs/ 对应 ID 下。

报告至少关联 Git 版本、模型与数据清单/校验值、类别和前后处理、运行命令、设备与软件版本、计时范围、预热与次数、结果或失败、尚未验证内容。不用日期日志代替实验原始证据。

## 查询与交接

从每日日志找产出，从小节工作笔记找任务状态，从资料索引找来源，从 E 目录找实验。具体模板见 [templates/records.md](templates/records.md)。

独立开发仓库中的状态表示真实进度，不填写假想的组长意见。未来收到外部意见时记录原文来源、日期、所针对的文件版本及处理结果；私聊敏感信息不直接上传。AI 自查、作者运行、非作者复现分别标注。
