# 写作流程与风格

本规范提取新手指南的规范性要求，并按个人第一阶段 SPEC 使用。它约束后续写作；项目初始化无需执行正文写作或增加确认手续。

## 按步骤推进

| 步骤 | 需要的输入 | 产出及保存位置 | 提示词 |
| --- | --- | --- | --- |
| 明确任务 | 个人 SPEC、相邻节内容 | 小节工作笔记中的任务卡及问题 | A |
| 调研 | 具体问题、已知版本 | 来源卡、资料索引、保存的原资料 | B |
| 整理理解 | 作者笔记、已读来源、真实记录 | 素材卡、事实与猜测的区分 | C |
| 形成提纲 | 已确认材料或明确缺口 | 小节提纲、图表及代码需求 | D |
| 整理正文 | 作者确认的提纲与材料 | 一个关键段落，再扩展到本节 | E |
| 图表与运行说明 | 实际工程或已确认方案 | assets 源文件、项目 README | F |
| 核查与修订 | 草稿、真实反馈、原资料 | 依据表、修改记录 | G、I |
| 试读与复现记录 | 真实读者意见或执行证据 | 工作笔记或 reports 中的检查记录 | J |
| 周提交 | 实际完成内容及记录 | 日期日志中的提交说明及产出链接 | K |

H 用于指定的章首章末汇总任务；本作者默认仅提供本节知识点、术语和实际引用条目，不自动承担整章统稿。

指南要求写正文前取得提纲确认或明确意见，结果段需真实条件、输出和判定要求。这里保留后续写作要求；本次初始化不生成或等待这些确认。

## 资料与引用

先列具体问题，优先官方文档、官方代码、原始论文和可靠教材。先找能够回答问题的少量关键材料，不凑数量。博客论坛是线索，AI 回答不是参考文献。

实际打开并定位内容后才标已核验；只找到标题、摘要或链接必须如实记录。保存当时使用的原文件、网页、代码版本及位置，原资料和笔记分开。受限资料记录合法访问方式，不自动上传。

来源卡使用`S02-001`一类稳定编号。小节初稿先写来源卡ID；章级汇总后使用实际分配的参考文献编号。不给未读资料编造页码，不把全部搜集资料都列为参考文献。实际实验以记录ID和报告路径关联。

## 正文

面向初学者，从项目中的问题开始，随操作引入必要概念。建议组织顺序：
问题与前后衔接 → 必要概念 → 方法、图表或短代码 → 输出及核对 → 常见错误和限制 → 后续交接。

这是组织方法，不要求每一步都成为独立标题。用连贯段落解释；比较用表格，操作用步骤，关系用图。纯概念内容按需要使用案例，不强行加入代码。

提纲按本节职责收敛，不统一凑成六段。2.6围绕计算图、算子、模型结构和形状变化组织；2.7围绕导出准备、opset与动态维度、结构接口检查和数值回归组织。跨节引入只说明作用和去向。图表尽量复用实际模型材料；代码清单先列功能，实际实现时再决定拆成几个文件。

术语首次出现时解释，同一中文译法与英文缩写保持一致。代码说明输入、作用和输出。正文保留稳定原理和必要核心片段，安装命令、完整工程及易变参数放项目 README。

避免“全面掌握”“高效赋能”等宣传表达，不用无证据的“显著提升”。将文献条件、自己的实测和预期分开。没有测量就留具体待补项，不用示例数字填结果表。

章首知识点与章末小结、术语、参考文献由章级汇总组织；个人交稿提供本节实际覆盖的条目及位置。习题不在当前初始化任务中增加。

## 正文与工作记录

正文文件按 CONTRIBUTING 命名。依据表、任务卡、AI 自查及修改讨论保留在工作记录中，不直接混入出版正文。

正式小节至少有一张有用的原创或重绘图表，保存可编辑源文件、图注及来源；概念示意与实测图区分。提示词模板首次 E 使用只生成一个关键段落；实际稿件以已保存、作者确认的文件为准，不以重新生成的文字代替定稿。

## 实验与检查

实验前写明问题、模型、输入、环境、保持不变的条件、计算方法、计时范围及判定要求。模型转换、程序运行、任务结果正确分别核对。成功与失败均保存；本机 CPU 时间不能作为板端 NPU 性能。

指南中的试读、非作者运行和审核是实际交稿时的证据要求，AI 不能模拟其结论。只读代码时写静态检查。需要口头补充的步骤应回写 README；变更模型或接口后重新验证受影响步骤。
