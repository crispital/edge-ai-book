## 一、整体工作目标与产出

### 工作目标

建立 MNIST 到真实业务的桥梁，讲数据采集、划分、泄漏、迁移学习、过拟合、错误样本和业务指标；以自有模型给出参数量、文件大小和 PC 端耗时，对照 1.5 节约束建立轻量化动机，说明“PC 端压缩—平台端实测”主线。

### 整体配套产出

- 自有数据目录示例。
- 迁移学习代码。
- 评价指标表和混淆矩阵示例。
- 自有模型基线度量报告。

## 二、3.1 从 MNIST 到真实业务任务

**主笔：黄章磊**

### 知识点

1. MNIST 与真实 RGB 任务在背景、光照、采集条件和类别分布上的差异。
2. 为何先做可控分类桥梁，再进入复杂检测部署。
3. 需求转化为类别定义、数据范围、模型任务和验收目标。
4. 串联自有数据、微调、评价、ONNX 导出和后续平台部署。

### 配套产出

- 教学数据与真实数据对照表。
- 桥梁项目流程图。

### 撰写要求

MNIST 能够用较低成本讲清训练、推理、ONNX 导出和结果验证，但真实应用通常面对 RGB 图像、复杂背景、类别不平衡、采集条件变化和有限数据量。本节比较教学数据集与真实业务数据的差异，解释为什么不能从 MNIST 直接跳到复杂检测平台，而需要先完成一个规模可控的自有数据项目。

本章选择“自有 RGB 图像分类”作为桥梁任务：整理图片，定义类别，划分数据集，微调预训练轻量模型，评价错误，导出 ONNX，并在后续章节部署。检测、分割、OCR 和跟踪则在分类桥梁建立后逐步展开。

## 三、3.2 自有 RGB 图像数据与迁移学习

**主笔：黄章磊**

### 知识点

1. 自有物品分类的类别定义、采集覆盖、标注目录、质量检查与类别不平衡。
2. 按采集批次或视频来源划分数据，避免相邻帧泄漏；训练与评估增强的区别。
3. 预训练 MobileNetV2、替换分类头、冻结特征与全网微调、学习率和 epoch。
4. 训练曲线、过拟合、混淆类别、错误样本分析；保存类别表和前处理并导出 ONNX、验证摄像头。

### 配套产出

- 可运行迁移学习项目。
- 数据划分记录。
- 固定测试集与模型交接包。

### 撰写要求

选择实验室物品、工业零部件、常见工具或其他容易采集的对象组成小型 RGB 分类数据集。讲解类别定义、图片采集、标签组织、类别不平衡和图像质量检查，并说明同一视频的相邻帧不能随意分散到训练集和测试集，以避免数据泄漏。

介绍训练集、验证集和测试集的划分方法，以及 Resize、裁剪、翻转、颜色扰动等基础数据增强。使用 MobileNetV2 等预训练轻量模型完成迁移学习，分别介绍固定特征提取器和微调整个网络两种基本方式，并说明学习率、冻结参数和训练轮次的作用。

模型训练后分析训练曲线、验证集表现、过拟合、混淆类别和错误样本。最终保存类别表、前处理参数、模型权重和版本信息，导出 ONNX，并在真实摄像头输入上检查效果，而不是只验证整理后的测试图片。本节产出的模型是第四章全部轻量化实验的公共对象。

## 四、3.3 任务评价指标与业务指标

**主笔：黄章磊**

### 知识点

1. 分类 Accuracy、Precision/Recall、混淆矩阵及类别不平衡影响。
2. 检测 IoU、AP/mAP 与阈值；分割 IoU/Dice；OCR 检测、识别与端到端评价。
3. 跟踪 ID 切换、连续性及案例所用指标，说明标注和评估条件。
4. 模型指标映射到误报、漏报、漏计、重复计数和响应时间；冻结全书测试口径。

### 配套产出

- 任务指标表。
- 错误样本示例。
- 业务验收指标模板。

### 撰写要求

不同任务需要不同评价指标。分类任务关注准确率、各类别 Precision/Recall 和混淆矩阵；目标检测关注 IoU、Precision、Recall、AP/mAP 和置信度阈值；图像分割关注 IoU、Dice 等像素级指标；多目标跟踪关注 ID 切换、轨迹连续性和所选案例采用的跟踪指标；OCR 则需要分别评价文本检测、文字识别和端到端结果。

| 任务 | 模型评价重点 | 应用评价关注点 |
| --- | --- | --- |
| 图像分类 | 准确率、各类别 Precision/Recall、混淆矩阵 | 错误类别、类别不平衡、真实输入稳定性 |
| 目标检测 | IoU、Precision、Recall、AP/mAP、置信度阈值 | 误报、漏报、重复框、目标尺寸与遮挡影响 |
| 图像分割 | IoU、Dice、像素准确率 | 边界质量、小区域漏分和后处理稳定性 |
| OCR | 文本检测指标、字符/文本准确率、端到端准确率 | 漏检、错识、字典覆盖和复杂背景适应性 |
| 多目标跟踪 | ID 切换、轨迹连续性及案例采用的跟踪指标 | 轨迹中断、遮挡恢复、重复计数和事件延迟 |
| 业务系统 | 由所用模型任务决定 | 误报、漏报、重复事件、有效响应时间和资源限制 |

模型指标必须进一步转换为业务验收要求。例如区域计数应用除了检测精度，还需要统计漏计、重复计数和事件响应时间；安防应用还需区分误报和漏报的不同代价。本节建立“任务指标—错误样本—业务后果—验收阈值”的对应关系，并为后续平台案例确定固定测试集和指标口径。本节建立的指标口径同样是第四章全部轻量化实验的精度评价标准。

## 五、4.1 为什么需要轻量化

**主笔：黄章磊**

### 知识点

1. 以 3.2 自有模型量化展示参数量、文件大小与 PC 耗时。
2. 把模型开销对应到 1.5 内存、时延、功耗等约束。
3. 精度保留与资源预算共同决定压缩目标。
4. PC 压缩与基线筛选、板端适配与实测的闭环；不把预期当结果。

### 配套产出

- 基线度量报告。
- 资源预算与压缩目标表。

### 撰写要求

以第三章 3.2 节训练出的自有模型为具体对象，给出其参数量、模型文件大小和 PC 端推理耗时，并对照第一章 1.5 节的端侧资源约束，说明“模型过大、过慢、内存超限”在端侧意味着什么。通过具体数字建立动机：轻量化不是可选的进阶技巧，而是端侧工程流程的常规环节。

同时说明本书轻量化主线的工作方式：第四章在 PC 端完成压缩并建立精度与开销的对照基线，第五至七章在真实硬件上检验收益是否兑现。压缩手段的选择必须始终围绕“任务指标不塌陷、资源开销可接受”两个目标。
